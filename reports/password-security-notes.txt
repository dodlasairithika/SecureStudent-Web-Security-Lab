Vulnerability: Plaintext Password Storage

Location:
users table / Login authentication

Severity:
High

Issue:
User passwords were initially stored as plaintext values in the database.

Example:
student1 → student123
admin → admin123

Risk:
If an attacker gains access to the database, they can directly see users' passwords. Users may also reuse the same password on other websites.

Root Cause:
Passwords were stored without cryptographic hashing.

Remediation:
Passwords were converted to secure password hashes using PHP password_hash().

Authentication was updated to use password_verify().

Verification:
1. Existing passwords were converted to hashes.
2. Normal login with the correct password succeeded.
3. Login with an incorrect password was rejected.

Final Status:
Fixed and verified.

Additional Security Improvement:

A secure user registration mechanism was implemented.
New passwords are automatically processed using password_hash()
before being stored in the database.

Verification:
A test user (student2) was registered successfully.
The password was stored as a hash beginning with $2y$ rather
than as plaintext.

Login using the original password was also verified successfully.
